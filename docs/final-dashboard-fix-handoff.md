# EternalGhost Dashboard Fix Handoff

## Scope completed

This update fixes the confirmed dashboard issues without changing the existing same-origin authentication model or ownership boundary. The dashboard continues to use the shared `BotManager`, Express REST endpoints, native browser `EventSource`, Zustand, React/Vite/Tailwind, and the existing JWT httpOnly cookie session.

| Area | Completed behavior |
| --- | --- |
| Realtime logs | `logger.botLog` is bridged once into the shared SSE event hub, so active `/api/events` streams receive `bot:log` events immediately. Detail-page REST snapshots merge with existing live entries instead of replacing them. |
| Mobile logs | TanStack Virtual rows use dynamic `measureElement` measurement, `data-index`, stable item keys, an end anchor, and append-following behavior. Long messages wrap and expand vertically rather than overlapping. |
| Theme | The global canvas, panels, inputs, buttons, alerts, token preview, navigation selection, and log colors now use an accessible charcoal dark palette. The document declares `color-scheme: dark`. |
| Chat and commands | Web and Discord both call `BotManager.chatBot`, which now reaches one `BotInstance.sendInput` dispatcher. A slash is a command marker only at character zero; the original message, including its slash, is sent through Mineflayer's documented `bot.chat()` method. Unconnected or non-alive bots are rejected. |
| `/select-bot` | Discord selection accepts a trimmed UUID prefix from 8 through 36 characters only when exactly one bot owned by the authenticated principal matches. Ambiguous prefixes return a specific request for more characters; malformed, foreign, and nonmatching inputs fail closed. Other REST lifecycle resolution remains canonical-UUID-only. |
| Navigation | The floating mobile hamburger was removed. The header owns the only navigation toggle at all breakpoints. |
| Forms | Token, chat, log filter, auto-scroll, bot configuration, and admin token controls have explicit unique IDs and names. |

## Realtime root cause

The supplied HAR proved that the browser successfully opened `GET /api/events` and held a `200 text/event-stream` response. The missing link was after the connection: `src/services/logger.js` emitted `botLog`, but no active runtime bridge forwarded those entries to `src/web/sse/eventHub.js`. The dormant notifier contained a similar idea but was not instantiated and could have duplicated broadcasts if enabled. The final implementation owns one module-level logger-to-event-hub bridge and keeps the optional notifier limited to lifecycle events.

The initial REST request in `BotDetailPage` was also made race-safe. Its response now merges with entries already appended by SSE and ignores stale responses after navigation cleanup. Log deduplication is based on timestamp, level, and message so an initial buffered line and its SSE counterpart do not appear twice.

## Chat transport decision

The official Mineflayer API documents `bot.chat(message)` and does not document a `bot.command()` method. The implementation therefore does not call an unsupported method. It classifies `/command` input centrally, preserves the exact original string, and sends that string through `bot.chat('/command')`, allowing the Minecraft server to interpret the leading slash. Input such as `  /login` remains ordinary chat because no trimming occurs during classification; only the empty-submit guard and UUID-selection input are trimmed.

## Verification

The final quality gate completed successfully. `git diff --check`, repository ESLint, the full Node test suite, the production Vite build, and `npm audit --omit=dev` all passed. The final test run reported **161 passing tests and 0 failures**. Browser verification against a local Vite preview confirmed the login route rendered with the dark canvas and surface colors; computed values were `rgb(15, 17, 21)` for the body and `rgb(23, 26, 33)` for panel/field surfaces, with `color-scheme: dark`. The token control rendered with `id="dashboard-token"` and `name="token"`.

The production test command used a harmless test-only environment for required configuration variables; no real token or secret was written to the repository. The open-source package should still be deployed with the operator's real `.env` values supplied outside version control.

## Chrome ad warning

The Chrome warning about intrusive ads is not generated by this dashboard's source: the repository contains no advertising iframe or ad script. It is a browser/domain-level intervention associated with the deployed origin and should be investigated in the host's Chrome Ad Experience Report if it persists. It is independent of the React update-depth and SSE fixes.
